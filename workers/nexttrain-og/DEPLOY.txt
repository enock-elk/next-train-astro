nexttrain-og — what YOU still need to do
========================================

Code + routes are ready. Two fixes remain on YOUR side after redeploy:

-------------------------------------------------------------------
1) REDEPLOY the Worker (after pulling latest code)
-------------------------------------------------------------------
   cd workers/nexttrain-og
   npm install
   npm run deploy

Then check:
   https://nexttrain.co.za/og/timetable.png?rt=pta-pien&dir=A&d=wd
   → must show station names + times (not a blank blue grid)

   https://nexttrain.co.za/og/share?rt=pta-pien&v=g&d=wd
   → HTML with og:title like "Pretoria → Pienaarspoort…"
   → View Page Source (not the live app) to confirm

-------------------------------------------------------------------
2) CRITICAL: turn OFF Cloudflare Bot Fight Mode
-------------------------------------------------------------------
Facebook / WhatsApp are being challenged ("Just a moment…") before they
reach the Worker. Free Bot Fight Mode CANNOT be skipped with WAF rules.

In Cloudflare Dashboard → nexttrain.co.za:

   Security → Bots → Bot Fight Mode → OFF

(If you are on Pro and use Super Bot Fight Mode instead, create a WAF
Custom Rule with Skip → Super Bot Fight Mode when User Agent contains
facebookexternalhit OR WhatsApp OR meta-externalagent.)

Without this step, Facebook Debugger will keep showing the homepage
train icon no matter what the Worker does.

-------------------------------------------------------------------
3) Re-scrape the NEW share URL
-------------------------------------------------------------------
Use this URL (not bare /?rt=…):

   https://nexttrain.co.za/og/share?rt=pta-pien&v=g&d=wd

Facebook Sharing Debugger → Scrape Again
Then send that link in a NEW WhatsApp chat.

In the debugger redirect path you must NOT see http-equiv refresh
chasing into /?rt=… (that was stealing the preview). After redeploy,
canonical / og:url should stay on /og/share?…

The fb:app_id warning is optional and safe to ignore for WhatsApp previews.
